# AutoWork Agent

**AutoWork Agent**는 Windows에서 동작하는 로컬 데스크톱 자동화 MVP입니다. 보안망 운영을 고려하여 로컬 LLM 연결 주소는 루프백 주소(`127.0.0.1`, `localhost`, `::1`)만 허용하며, 외부 네트워크 우회나 클라우드 AI 연결 기능은 제공하지 않습니다. 마우스 클릭과 키보드 입력을 기록해 JSON 작업 파일로 저장하고, 같은 순서로 재생할 수 있습니다. 또한 화면 캡처, OCR 문자, 현재 활성 창의 접근성 컨트롤 정보를 로컬 OpenAI 호환 AI 서버에 전달하여 다음 업무 단계를 제안할 수 있습니다.

> AI가 임의로 컴퓨터를 조작하지 않도록, AI가 만든 계획은 화면에 먼저 표시하고 사용자가 최종 승인해야 실행됩니다.

## 현재 제공 기능

| 영역 | 지원 내용 | 동작 방식 |
|---|---|---|
| 기록 | 전역 마우스 클릭, 키보드 누름·해제, 이벤트 간 지연시간 | `pynput` |
| 편집 | 기록된 단계 선택 삭제 및 `Delete` 키 단축키 | Tkinter Treeview |
| 재생 | 클릭 좌표, 키보드 입력, 지연시간 순서 재현, 일시정지·재개 | `pyautogui` + 중지/일시정지 이벤트 |
| 화면 관찰 | 전체 화면 캡처, OCR, 활성 창 이름, Windows UI Automation 컨트롤 정보 | `Pillow`, `pytesseract`, `pywinauto` |
| 로컬 AI | Ollama·LM Studio 등 OpenAI 호환 서버 연결 | HTTP `/v1/chat/completions` |
| UI 요소 기반 계획 | Gemma는 좌표가 아니라 실제 UIA `element_id`를 선택하고 실행 직전에 현재 화면에 다시 존재하는지 검증 | Pydantic JSON Schema + Windows UI Automation |
| dry-run | 기본값은 실제 클릭·입력 없이 계획과 UI 요소만 검증 | 설정 탭에서 명시적으로 해제 |
| 안전 | 허용 동작 검증, 화면 밖 좌표 차단, 승인 대화상자, 단계별 재관찰·제한 재시도, PyAutoGUI 긴급 중지, 입력·엔드포인트 제한 | 내장 검증 로직 |
| 저장 | 버전 2 JSON, 단계·좌표·지연시간 검증, 기록 화면 크기 메타데이터, 원자적 저장, 파일 크기 제한 | `%LOCALAPPDATA%\AutoWorkAgent\workflows` |

현재 버전은 **범용 화면 자동화 기반**입니다. Excel, 브라우저, PDF 뷰어, 한글 문서처럼 UI가 서로 다른 프로그램에서도 동작할 수 있지만, 프로그램별 내부 구조를 직접 조작하는 전용 커넥터가 아니라 화면·키보드·마우스 중심으로 동작합니다. 따라서 창 크기, 배율, 문서 상태가 달라지면 기록 작업을 다시 만들거나 AI 계획을 재검토해야 합니다.

## Windows에서 실행

### 1. 소스 폴더 준비

이 폴더 전체를 Windows PC로 복사합니다. Windows 10 또는 Windows 11에서 Python 3.11 이상을 사용하도록 권장합니다.

### 2. 자동 설치와 실행

`run_windows.bat`을 더블클릭하거나 PowerShell에서 아래 명령을 실행합니다.

```powershell
.\run_windows.bat
```

스크립트는 가상환경을 만들고 `requirements.txt`의 의존성을 설치한 뒤 프로그램을 실행합니다.

### 3. 기록·재생 사용

프로그램에서 **기록 시작**을 누르고 Excel, 한글, PDF 뷰어 또는 브라우저로 전환하여 작업합니다. 다시 프로그램으로 돌아와 **기록 중지**를 누르고 작업을 저장하면 됩니다. 재생 전에 현재 창 크기와 화면 배율이 기록 당시와 같은지 확인하십시오.

기록 시 화면 크기를 작업 파일에 함께 저장합니다. 목록에서 불필요한 단계를 선택한 뒤 **선택 단계 삭제** 또는 `Delete` 키로 제거할 수 있습니다. 재생 전에 현재 화면 크기가 기록 당시와 다르면 좌표가 어긋날 수 있다는 경고를 표시하고, 사용자가 계속 진행할지 결정합니다.
재생 중에는 **재생 일시정지**로 현재 단계 사이에서 작업을 잠시 멈추고 화면을 확인한 뒤 **재생 재개**할 수 있습니다. 마우스를 화면 **왼쪽 위 모서리**로 이동하면 PyAutoGUI 긴급 중지 기능이 작동하며, `Ctrl + Alt + F12`도 기록·재생·AI 실행을 중지합니다.

## 로컬 AI 연결

기본 설정은 다음과 같습니다.

```text
주소: http://127.0.0.1:11434/v1
모델: gemma4:e2b
```

Ollama나 LM Studio처럼 OpenAI 호환 채팅 API를 제공하는 **로컬 서버만** 실행한 뒤, **설정** 탭에서 주소와 모델 이름을 바꾸면 됩니다. 기본 모델명은 `gemma4:e2b`로 설정되어 있으며, 실제 설치된 서버에서 표시되는 모델 태그가 다르면 설정 탭에서 그 태그를 그대로 입력해야 합니다. 주소는 보안상 루프백 주소의 `/v1` 경로만 허용되고, 외부 도메인·다른 컴퓨터 주소·인증정보·query string은 차단됩니다. 응답 제한 시간은 5~600초 범위로 검증됩니다. 외부 API에 연결하거나 보안망을 우회하는 기능은 포함하지 않습니다. 로컬 AI 없이도 기록·재생 기능은 독립적으로 사용할 수 있습니다.

화면 이미지까지 모델에 보내려면 **가능한 경우 화면 이미지도 로컬 모델에 전달**을 선택하십시오. 해당 모델이 이미지 입력을 지원하지 않으면 OCR과 접근성 컨트롤 정보만 사용하도록 설정을 끄는 것이 안정적입니다.

## AI 업무 보조 사용

**AI 업무 보조** 탭에 목표를 자연어로 입력하고 **화면 관찰 후 계획 생성**을 누릅니다. 프로그램은 현재 화면을 캡처하고 OCR·접근성 정보를 수집하여 로컬 AI에 계획을 요청합니다. 반환된 계획은 JSON 형태로 화면에 표시됩니다.

Gemma는 현재 화면에서 수집한 UIA 요소의 `element_id`를 선택합니다. 좌표를 직접 생성하거나 화면에 없는 버튼을 상상한 계획은 검증 단계에서 거부됩니다. 현재 AI가 실행하도록 허용된 동작은 `click`, `double_click`, `type`, `hotkey`, `scroll`, `wait`입니다. 셸 명령, 파일 삭제, 결제, 문서 전송, 게시, 로그인 정보 입력은 계획 검증 단계에서 차단하거나 기본적으로 자동 실행하지 않습니다.

**설정** 탭의 `AI 계획은 실제 입력 없이 검증만 수행(dry-run)`은 기본적으로 켜져 있습니다. 처음에는 이 상태로 계획과 element_id가 맞는지 확인하십시오. 실제 업무를 수행하려면 사용자가 직접 dry-run을 해제하고 설정을 저장한 뒤, 다시 최종 확인을 거쳐야 합니다. 실행 중에는 각 단계 직전에 화면을 다시 관찰하고 UI 요소 존재·활성·영역을 검증합니다. `expected_texts`가 계획에 포함되면 실행 후 OCR·UIA 텍스트로 기대 결과를 확인하며, 일시적인 요소 미발견이나 로딩은 제한적으로 재시도합니다. 목표는 4,000자, 텍스트 입력은 100,000자, AI 계획은 30단계까지 제한됩니다. 팝업, 로그인 만료, 오류, 위험 동작은 자동 재시도하지 않고 중단합니다.

## 개발 테스트

개발 환경에서는 다음 명령으로 테스트 의존성을 설치하고 회귀 테스트를 실행할 수 있습니다.

```powershell
py -3 -m pip install -r requirements-dev.txt
py -3 -m pytest -q
```

현재 테스트는 작업 파일 round-trip, 버전·화면 크기 메타데이터·단계 삭제·입력 검증, 로컬 엔드포인트 제한, AI 계획 안전성, 오류 보고서, 재생 일시정지 상태를 확인합니다.
Windows 전용 입력 장치와 Tkinter 화면 자체는 샌드박스 테스트 대상이 아니므로, 배포 전 승인된 Windows PC에서 기록·재생·OCR·UI Automation을 별도로 점검해야 합니다.

## 직접 빌드하여 실행 파일 만들기

Windows에서 `build_windows.bat`을 실행하면 `dist\AutoWorkAgent.exe`가 생성됩니다.

```powershell
.\build_windows.bat
```

실행 파일을 만들 때도 처음 한 번은 Python과 의존성 설치가 필요합니다. OCR을 사용할 경우 Windows용 Tesseract와 한국어 언어 데이터가 별도로 필요할 수 있습니다. OCR이 준비되지 않아도 기록·재생과 AI 계획의 접근성 정보 사용은 계속할 수 있습니다.


## 예외 상황과 디버깅

자동화 중 오류가 발생하면 해당 동작은 즉시 중지되고, 현재 작업명·실패 단계·오류 유형·traceback이 로컬 오류 보고서로 저장됩니다. 기본 설정에서는 예외 발생 시 화면 캡처도 함께 저장합니다. GUI의 **진단·로그** 탭에서 최근 로그를 확인할 수 있으며, `로그 폴더 열기`로 `%LOCALAPPDATA%\\AutoWorkAgent`를 열 수 있습니다. 재생 중에는 `Ctrl + Alt + F12` 또는 화면 왼쪽 위 모서리 이동으로 긴급 중지할 수 있고, AI 계획 실행 중에는 **AI 실행 중지** 버튼을 사용할 수 있습니다.

오류 보고서와 화면 캡처에는 업무 문서나 개인정보가 포함될 수 있으므로, 보안망 운영 시 보존 기간과 접근권한을 보안 담당자 기준으로 관리하십시오.

## 보안망 운영 시 주의사항

보안망에서 사용할 때는 조직의 공식 승인 절차에 따라 설치파일과 모델파일을 반입하고, 방화벽 우회 규칙이나 원격 접속 규칙을 추가하지 않아야 합니다. 상세한 허용 통신 범위와 검토 항목은 `SECURITY_OFFLINE.md`에 정리되어 있습니다.

## 제한 사항과 다음 확장 방향

마우스 좌표 기록은 창 위치나 화면 배율이 달라지면 안정성이 떨어질 수 있습니다. AI 업무 보조는 이 한계를 줄이기 위해 UIA `element_id`와 OCR 문자를 우선 사용하지만, 레거시 앱이 접근성 정보를 제공하지 않는 경우에는 AI 계획을 실행하지 않고 기록·재생 방식으로 전환해야 합니다. 다음 단계에서는 Excel의 셀 주소를 인식하는 전용 어댑터와 한글·PDF의 문서 상태 검증을 추가하는 것이 적절합니다.

또한 AI가 직접 파일을 지우거나 외부로 전송하지 못하도록 현재 구조를 유지하고, 파일 쓰기·메일 발송·결재·게시와 같은 고위험 동작은 별도의 명시적 승인 단계로 분리해야 합니다.
