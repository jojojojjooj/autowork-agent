# AutoWork Agent

**AutoWork Agent**는 Windows에서 동작하는 로컬 데스크톱 자동화 MVP입니다. 로컬 LLM 연결 주소는 루프백 주소(`127.0.0.1`, `localhost`, `::1`)의 `/v1` 경로만 허용하며, 외부 네트워크 우회나 클라우드 AI 연결 기능은 제공하지 않습니다. 마우스·키보드 기록/재생, 화면 캡처·OCR, Windows UI Automation 기반 AI 계획을 제공합니다.

> AI 계획은 화면에 먼저 표시되고 사용자의 최종 승인을 거쳐야 실행됩니다. 기본 모드는 실제 입력이 없는 `dry-run`입니다.

## 현재 제공 기능

| 영역 | 지원 내용 | 동작 방식 |
|---|---|---|
| 기록 | 전역 마우스 클릭, 키보드 누름·해제, 이벤트 간 지연시간 | `pynput` |
| 편집 | 선택 단계 삭제 및 `Delete` 키 | Tkinter Treeview |
| 안전 점검 | 실행 전 단계 수·동작 종류·화면 크기·대상 창을 비파괴적으로 확인 | Workflow inspection report |
| 단계별 승인 | 각 입력 단계마다 실행 전 확인 | Tkinter confirmation dialog |
| 재생 | 좌표·UIA 템플릿·키보드 동작 재현, 일시정지·재개, 실패 단계 재개, 긴급 중지, 중복 실행 방지 | `pyautogui` + 실행 잠금 |
| 무결성 | 저장 시 로컬 HMAC 서명, 변조 파일 차단 | `workflow.key` |
| 백업 | 기존 작업을 덮어쓰기 전 자동 백업, 최대 20개 보존, GUI 복원 | 로컬 `workflow_backups` |
| 운영 | 앱 실행 중 저빈도 예약 재생, 실행 통계와 감사 이력 용량 제한 | 로컬 스케줄러·JSONL |
| 화면 관찰 | 전체 화면 캡처, OCR, 활성 창, Windows UI Automation 컨트롤 | `Pillow`, `pytesseract`, `pywinauto` |
| 로컬 AI | Ollama·LM Studio 등 OpenAI 호환 서버, 의미 기반 요소 재바인딩, 실패 복구 계획 | HTTP `/v1/chat/completions` + UI 의미 단서 검증 |
| AI 검증 | UIA `element_id`, 화면 영역, 신뢰도, 허용 키와 동작 검증 | Pydantic + 정책 검사 |
| 보존 관리 | 30일 지난 캡처·오류 아티팩트 정리, 진단 로그 민감 필드 마스킹 | 로컬 파일 시스템 |
| 자연어 템플릿 | `{{변수}}` 목표 저장 및 불러오기 시 변수 입력 | 로컬 JSON 템플릿 |
| 안전 프로필 | 일반·공공문서·브라우저·Excel별 허용 동작·승인 수준·단계 수·총 대기시간 예산 적용 | `app/policies.py` |
| 문서 검색 | 승인된 최대 5개 로컬 루트의 제한된 파일 검색 | 로컬 읽기 전용 검색 |
| 결과 검증 | `expected_texts`를 OCR·UIA 텍스트와 대조해 성공 여부 확인 | 실행 후 재관찰 |
| 사전 검토 | 실행 전 단계 수·동작/위험도·총 대기시간·결과 확인 문구·정책 위반 사유 요약 | 로컬 결정적 검토 |
| 엔터프라이즈 모니터링 | 운영 상태 heartbeat, 실패·성공률 경보, run_id 기반 실행 추적, 개인정보 제외 지원 패키지 | 로컬 JSON 상태·진단 패키지 |
| 실행 리포트 | 실행별 성공·실패·중지, 단계 범위, 소요시간, 오류 유형, 정책 프로필 요약 | 로컬 JSON 원자 저장·최대 100개 |

현재 버전은 범용 화면 자동화 기반입니다. Excel, 브라우저, PDF 뷰어, 한글 문서 등에서 동작할 수 있지만 전용 커넥터가 아니므로 창 위치·화면 배율·문서 상태가 달라지면 작업을 재기록하거나 AI 계획을 재검토해야 합니다.

## Windows 설치 및 실행

Windows 10/11과 Python 3.11 이상을 권장합니다. 저장소 전체를 Windows PC로 복사합니다.

### 온라인 환경

```powershell
.\install_windows.bat
.\run_windows.bat
```

설치 스크립트는 `requirements.lock.txt`의 고정 버전 의존성을 설치하고 `.venv\READY.txt`를 생성합니다. 실행 스크립트는 의존성을 자동 다운로드하지 않으며 설치 완료 환경에서만 실행됩니다.

### 오프라인 보안망

승인된 준비 환경에서 `requirements.lock.txt`와 모든 전이 의존성 wheel을 확보하고 해시를 확인한 뒤 반입합니다. wheel 디렉터리가 `D:\approved-wheels`이면 다음과 같이 설치합니다.

```powershell
.\install_windows.bat D:\approved-wheels
.\run_windows.bat
```

설치파일·wheel·Tesseract 언어 데이터·LLM 모델 파일은 조직의 공식 반입 절차를 따르십시오. 상세 내용은 [`SECURITY_OFFLINE.md`](SECURITY_OFFLINE.md)에 있습니다.

## 기록·재생

**기록 시작**을 누른 뒤 대상 프로그램으로 전환해 작업하고, **기록 중지** 후 저장합니다. 기록 당시의 주 화면 크기가 작업 파일에 저장되며, 재생 시 현재 화면 크기가 다르면 경고가 표시됩니다. 목록에서 단계를 선택해 **선택 단계 삭제** 또는 `Delete` 키로 제거할 수 있습니다.

재생은 한 번에 하나만 허용됩니다. **재생 일시정지**로 현재 단계 사이에서 멈추고 **재생 재개**할 수 있습니다. 마우스를 화면 왼쪽 위 모서리로 이동하거나 `Ctrl + Alt + F12`를 누르면 긴급 중지됩니다.

재생 또는 저장 전에 **안전 점검**을 누르면 작업의 유효성, 단계별 동작 수, 기록 화면과 현재 화면의 차이, 기록된 대상 창을 비파괴적으로 확인할 수 있습니다. 점검 결과가 실패하면 재생이 차단되며, 화면 크기 차이와 같은 경고는 사용자가 확인한 뒤 진행해야 합니다.

작업 JSON은 키 입력과 좌표를 포함할 수 있으므로 신뢰할 수 있는 파일만 불러오십시오. 파일 로드·저장·실행 시 버전, 필드, 단계 수, 동작 종류, 좌표, 지연시간, 버튼, 키 이름을 검증합니다. 새로 저장하는 작업은 이 PC에만 보관되는 HMAC 서명을 포함하며, 서명이 있는 파일이 변조되면 불러오기를 거부합니다. 기존 파일을 덮어쓸 때는 `workflow_backups`에 자동 백업하고 최근 백업 최대 20개를 보존합니다. **백업 복원**은 선택한 백업의 서명이 있으면 검증한 뒤 현재 작업을 덮어쓰며, 레거시 무서명 백업도 사용자의 명시적 확인 후 복원할 수 있습니다. 작업 파일은 원자적으로 저장되고 최대 10MB로 제한됩니다.

실행 중 오류가 발생하면 **실패 단계부터 재개** 버튼을 사용할 수 있습니다. 재개는 다시 실행될 입력 동작이 있음을 명확히 알리고, 사용자가 확인한 후에만 시작합니다. 앱이 종료되거나 재시작되어도 실행 체크포인트가 작업 파일 경로·서명·다음 단계만 저장하므로 **재시작 복구** 버튼으로 안전하게 복구할 수 있습니다. 입력 내용과 전체 단계 목록은 체크포인트에 저장하지 않습니다. 목록의 **단계별 승인**을 켜면 각 동작마다 개별 승인 대화상자가 표시됩니다.

## 로컬 AI 연결

기본값은 다음과 같습니다.

```text
주소: http://127.0.0.1:11434/v1
모델: gemma4:e2b
```

Ollama나 LM Studio를 로컬에서 실행한 뒤 **설정** 탭에서 주소와 모델 이름을 지정합니다. 주소는 루프백 호스트와 `/v1` 경로만 허용하며 인증정보·query string·fragment·외부 호스트는 차단됩니다. 응답 제한 시간은 5~600초로 제한됩니다. **연결 점검**은 사용자 데이터나 프롬프트를 보내지 않고 `/models` 응답만 확인해 서버 도달 여부와 모델 목록을 보여줍니다.

화면 이미지를 로컬 모델에 보내려면 해당 모델이 비전 입력을 지원하는지 확인한 뒤 설정하십시오. OCR과 오류 캡처에는 이메일·전화번호·주민등록번호 형식의 문자열을 가능한 범위에서 마스킹합니다. 로컬 AI가 없어도 기록·재생은 독립적으로 사용할 수 있습니다.

### 예약 실행

**설정** 탭에서 60초부터 24시간 사이의 간격을 지정하고 **예약 시작**을 누르면 앱이 실행 중인 동안 현재 Workflow를 반복 재생합니다. 예약 실행은 안전을 위해 앱이 꺼져 있을 때 Windows 서비스나 작업 스케줄러처럼 백그라운드에서 자동 시작하지 않으며, 기록 중·재생 중·유효하지 않은 작업은 건너뜁니다. 실제 입력이 포함되므로 운영 전 안전 점검과 단계별 승인을 먼저 수행하십시오.

진단·로그 탭의 실행 이력 영역에는 이벤트 수, 완료·실패 횟수, 성공률, 최근 이벤트가 표시됩니다. 개별 재생과 AI 계획 실행은 짧은 `run_id`와 소요시간으로 시작·성공·실패·중지 이벤트를 연결해 원인 분석을 돕습니다. 운영 상태는 30초 heartbeat로 갱신되며, 3건 이상 반복 실패 또는 기준 이하 성공률을 로컬 경보로 표시합니다. **지원 패키지 저장**은 Workflow 단계·키 입력·화면 캡처 원문을 제외한 상태 스냅샷, 최근 감사 이벤트, 최근 로그, 오류 보고서 목록만 JSON으로 내보냅니다. 이력은 로컬 JSONL로만 저장되고 최대 5MB 범위에서 오래된 기록이 정리됩니다. 별도의 `run_reports` 폴더에는 입력값과 전체 단계 원문을 포함하지 않는 실행별 JSON 요약 리포트가 원자적으로 저장되며 최근 100개만 유지됩니다.

## AI 업무 보조

**AI 업무 보조** 탭에 목표를 입력하고 **화면 관찰 후 계획 생성**을 누릅니다. 현재 화면의 OCR·UI Automation 정보를 로컬 AI에 전달하고, 반환된 계획과 함께 결정적 **사전 검토 결과**를 표시합니다. 사전 검토에는 단계 수, 동작·위험도별 개수, 총 대기시간, 결과 확인 문구 수, 현재 안전 프로필의 한도와 정책 위반 사유가 포함됩니다.

허용 동작은 `click`, `double_click`, `type`, `hotkey`, `scroll`, `wait`뿐입니다. 좌표 직접 지정, 현재 화면에 없는 `element_id`, 허용되지 않은 키, 위험한 시스템 단축키는 거부됩니다. 화면 갱신으로 `element_id`가 바뀐 경우에도 AI가 함께 제시한 `element_role`, `element_name`, `element_control_type`으로 현재 화면에서 정확히 하나의 요소만 식별될 때에만 의미 기반 재바인딩을 허용합니다. 후보가 없거나 둘 이상이면 실행하지 않습니다. `type`은 쓰기 동작으로 간주하여 사용자 확인이 필요하며, 비밀번호·주민등록번호·토큰 등 민감정보 필드로 보이는 요소에는 자동 입력하지 않습니다.

사전 검토가 실패하거나 정책 위반 사유가 있으면 실행 버튼이 비활성화되고, 최종 확인 단계에서도 다시 차단됩니다. 실행 직전 각 단계에서 화면을 다시 관찰하고 UI 요소의 존재·가시성·활성 상태·영역을 검증합니다. 계획에 `expected_texts`가 있으면 클릭·입력 후 OCR과 UIA 텍스트를 다시 관찰해 기대 문구를 확인합니다. 결과를 확인하지 못하면 안전하게 중단합니다.
읽기성 UI 탐색은 제한적으로 재시도할 수 있지만, 입력·단축키·쓰기·제출·삭제 가능 동작은 자동 재시도하지 않고 사용자 개입을 요구합니다. 셸 명령, 파일 삭제, 결제, 전송, 게시, 로그인 정보 입력, 결재는 자동 실행 대상이 아닙니다. 의미 기반 재바인딩은 화면 내부의 단일 UIA 후보를 찾는 기능이며, 문서 내용을 추론하거나 민감한 대상을 자동 승인하는 기능이 아닙니다.

재생 실패 후에는 오류 유형·실패 단계·현재 화면을 로컬 AI에 전달해 복구 계획을 제안할 수 있습니다. 복구안은 자동 실행되지 않고 계획 화면에 표시되며, 기존 최종 승인과 안전 프로필 검증을 다시 통과해야 합니다. **자연어 템플릿 저장**은 `{{month}}`, `{{target}}` 같은 변수를 저장하고 불러올 때 값을 입력받습니다. 설정 탭의 안전 프로필과 승인 문서 루트를 함께 사용하면 업무별 계획 범위를 제한할 수 있습니다. 문서 검색은 승인된 루트의 파일명과 작은 텍스트 파일 일부만 읽으며 파일을 수정하지 않습니다.

## 테스트 및 빌드

개발 테스트는 다음과 같이 실행합니다. 현재 회귀 테스트는 41개이며, 로컬 문서 검색은 임시 승인 디렉터리만 대상으로 합니다.

```powershell
$env:PYTHONPATH = "."
pytest -q
```

의존성 설치가 완료된 환경에서 다음 명령으로 실행 파일을 만듭니다.

```powershell
.\build_windows.bat
```

`dist\AutoWorkAgent.exe`가 생성됩니다. 빌드 스크립트는 패키지를 새로 다운로드하지 않습니다. OCR을 사용할 경우 Windows용 Tesseract와 `kor`·`eng` 언어 데이터가 별도로 필요합니다.

## 민감정보와 오류 처리

오류 보고서에는 작업명·실패 단계·오류 유형·traceback이 포함될 수 있으며 설정에 따라 화면 캡처도 저장됩니다. 실행 요약 리포트에는 작업명·단계 수·단계 범위·소요시간·오류 유형·정책 프로필만 저장하고 입력값과 전체 단계 원문은 저장하지 않습니다. 시작 시 `cache`, `errors`, `debug_snapshots` 폴더의 기본 30일 이상 지난 파일과 초과 백업을 정리합니다. 작업 JSON과 실행 리포트는 자동 삭제하지 않으므로 ACL과 보존기간을 별도로 관리하십시오.

진단 컨텍스트와 dry-run 로그에서는 `text`, `value`, `password`, `token`, `secret` 등 민감 필드를 마스킹합니다. 화면 캡처와 작업 파일 원문까지 익명화하는 기능은 아니므로, 업무 종료 후 승인된 절차에 따라 삭제하고 접근권한을 제한하십시오.

## 다음 단계 고도화 로드맵

현재 구현은 **Phase 1 실행 신뢰성**까지를 대상으로 합니다. 체크포인트·실패 단계 재개·재시작 복구와 개인정보를 제한한 실행 리포트를 구현했으며, 아래 Phase 2 이후 항목은 향후 개발 계획입니다.

| 단계 | 목표 | 계획 기능 | 상태 |
|---|---|---|---|
| Phase 1 | 실행 신뢰성 | 체크포인트, 재개·복구, 실행 이력·요약 리포트 | 구현 완료 |

## 제한 사항

레거시 앱이 접근성 정보를 제공하지 않으면 AI 계획을 실행하지 않고 기록·재생 방식으로 전환해야 합니다. 현재 문서 검색은 텍스트 파일과 파일명 중심의 보수적 검색이며, PDF·Excel·한글 내부 내용을 직접 추출하지 않습니다. 복구 계획도 자동 실행하지 않고 사용자가 다시 승인해야 합니다. 고위험 기능을 추가하더라도 별도 승인 단계와 감사 로그를 거쳐야 합니다.
